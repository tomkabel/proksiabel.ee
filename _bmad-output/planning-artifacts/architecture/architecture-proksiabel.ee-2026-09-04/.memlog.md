- (decision) Token Source is the existing Tailwind v4 @theme block in src/index.css, NOT a new tokens.json + generator. Tailwind v4 CSS-first already emits CSS custom properties AND the Tailwind theme from one authored block — a generator would reimplement a native platform feature. Answers PRD OQ-5; conflicts with FR-22/FR-23 mechanism wording.
- (decision) Only real drift risk is DESIGN.md YAML frontmatter (colors/typography duplicated by hand). Solve with a one-way generator+check script (DESIGN.md frontmatter generated from @theme, verified in build), not a full pipeline.
- (constraint) Claim-bearing content must live in typed data modules (src/data/*, src/i18n/translations.ts), never as literals in JSX — this is what makes the FR-20 Legal Read auditable against files instead of a component sweep.
- (decision) ET/EN parity becomes type-enforced: et satisfies the en shape. Today translations.ts is 'as const' with independently inferred locales, so a missing ET key compiles clean. Closes SM-5 mechanically.

- (constraint) No third-party network origin at build or runtime (GDPR): fonts via @fontsource npm packages, self-hosted; token pipeline fetches nothing.
- (assumption) No new route is needed for the rebrand — Heritage is a homepage section, not a page.
